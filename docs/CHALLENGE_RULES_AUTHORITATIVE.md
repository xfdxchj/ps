## 四、掩码结构（框架改动）

### 现状
- `Dungeon.challenges` 是 **`int`**，`Challenges.MAX_VALUE = 4095`（12 位）
- `SPDSettings.challenges()` 用 `getInt(KEY, 0, 0, MAX_VALUE)` **硬夹取到 4095**
- `GamesInProgress.Info.challenges` 也是 `int`，存档 `Bundle` 存 `int`
- `Challenges.MAX_CHALS = 12` 用于随机挑战骰子

### 约束
96 条新规则 + 12 条已有 = **108 位**，`int` 装不下，`long` 也不够。

> ⚠️ 上句的 108 是早期错误统计，**实际为 118 位**（106 待实装 + 12 已实装），
> 位号最大到 138。见本节开头更正。

### 方案（推荐）
1. **新增 `ChallengeMask` 类**：内部用 `long[]`（或 `BitSet`）承载任意位宽
2. **索引与位号解耦**：位号 = 表 ID（1..138），**不是数组下标**（因为有编号断层）
   - `bit = ID`，最大 138 → 需 3 个 `long`
3. **兼容层**：
   - `Challenges.MASKS[]`（旧 int 掩码）保留，用于老存档读取
   - `Dungeon.challenges` 保留为 int（旧逻辑 20 处 `isChallenged` 调用继续工作）
   - 新增 `Dungeon.challengeMask`（`ChallengeMask`）承载全部规则
   - `Challenges.isItemBlocked` 等旧入口继续走 int
4. **存档**：`Bundle` 支持 `int[]`；用 `put("challenges_hi", long[])` 或转成 `int[]` 四段存
5. **清理 `DHXD = 8192`**（越界死常量）

### 迁移原则
**不破坏旧存档**：老存档读出的 int 掩码，映射到新结构的低 12 位即可。

## 五、通过等级计算

```
通过等级 = ∑ (启用规则的等级数值)
```

- 结算时遍历所有启用规则，累加其 `level`
- 需要区分「正式规则」与「测试/娱乐规则」（便利测试包不应计入）
- 原表倾向分档（供 UI 展示与配色）：
  - 高风险 / 怪物强化（3/2）— 显著提升难度
  - 资源压力（2/1）— 削弱经济或物资
  - 双刃剑（2/1）— 收益与风险并存
  - 玩家收益（3/2/1）— 降低难度
  - 0难度 / 中性 / 娱乐（1）— 梗向或外观

> **三类关系要分清**：
> - **互斥（exclusive）** — 不能同时启用，UI 强制置灰
> - **联动（synergy）** — 可以同时启用，且效果叠加/有特殊交互，UI 只提示
> - **限制（restriction）** — 可以同时启用，但其中一条的功能对另一条无效，UI 只警告
> - **前置（prerequisite）** — 必须满足才能勾选，UI 置灰（132 专用）
