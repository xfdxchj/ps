## 一、黑兔戒指修复说明

### 1.1 设计效果

权威表对黑兔戒指的描述：

> 攻击时回合数加一（表现为可以一回合释放两次攻击，类似手里剑，**每回合最多触发一次**）。该戒指无法升级。

因此预期行为是：

- 每回合**第一次命中**后，这一击**不消耗回合**（返还一个回合）；
- 于是同一回合内还能再出手一次（或改为移动、喝药）—— 即「每回合最多攻击两次」；
- **每回合**最多触发一次，避免无限连击；
- 戒指无法升级。

### 1.2 实际现象：整局只触发一次

日志里第一只怪触发了，第二只之后再也不触发：

```
[战斗] 近战尝试 Hero → Rat  位置=635→634  距离=1  存活=true
[战斗] 伤害结算 Hero → Rat  dmg=7  HP前=8/8  dr=1
[战斗] 【127 黑兔戒指】标记免费出手          ← 触发
[战斗] 【127 黑兔戒指】本次出手不消耗回合      ← 这一击免费
[战斗] 近战尝试 Hero → Rat  位置=635→634  距离=1  存活=true
[战斗] 伤害结算 Hero → Rat  dmg=8  HP前=1/8  dr=1
[GAME] 你击败了啮齿小鼠。

[战斗] 近战尝试 Rat → Hero  位置=629→630  距离=1  存活=true
[战斗] 近战尝试 Hero → Rat  位置=630→629  距离=1  存活=true
[战斗] 伤害结算 Hero → Rat  dmg=3  HP前=8/8  dr=0    ← 本回合第一次命中，却没有【标记免费出手】
[战斗] 近战尝试 Rat → Hero  位置=629→630  距离=1  存活=true
[战斗] 伤害结算 Rat → Hero  dmg=2  HP前=20/20  dr=1  [玩家]
[战斗] 近战尝试 Hero → Rat  位置=630→629  距离=1  存活=true
[战斗] 伤害结算 Hero → Rat  dmg=8  HP前=5/8  dr=0
```

「每回合重置」的计数没有重置，所以从第二次命中开始永远判定为「本回合已触发过」。

### 1.3 根因

`RabbitRing.shouldRefundTurn()` 创建追踪 buff 时用了**带 duration 的重载**：

```java
t = Buff.affect(hero, RabbitRingTracker.class, 9999f);   // 问题所在
```

带 duration 的重载语义**不是**「这个 buff 活 9999 回合」，而是：

```java
append(target, class);     // 挂上 buff，此时 Actor.time = now
buff.spend(duration);      // Actor.time += 9999
```

SPD 的 actor 调度每轮取 `time` 最小的 actor 调 `act()`（见 `Actor.process()`），
所以 `spend(9999)` 的实际含义是：**这个 buff 的下一次 `act()` 要等 9999 个 tick 之后才会被调用**。

而「本回合是否已触发」这个计数**恰好只在 `RabbitRingTracker.act()` 里被清零**：

```java
@Override
public boolean act(){
    usedThisTurn = false;    // ← 每回合重置，但 act() 根本不会被调用
    freeAttack   = false;
    spend(TICK);
    return true;
}
```

于是：

1. 第一次命中 → `usedThisTurn = true` → 正常发出免费一击；
2. `act()` 要等 9999 个 tick 才被调用 → `usedThisTurn` 永远是 `true`；
3. `shouldRefundTurn()` 之后永远返回 `false` → 整局再也不触发。

一句话：**「每回合重置」写在了几乎永远不会被调用的 `act()` 里。**

### 1.4 修改内容

`shouldRefundTurn()` 与 `markFreeAttack()`：把 tracker 改成**不带 duration**地挂载。

```diff
- t = Buff.affect(hero, RabbitRingTracker.class, 9999f);
+ t = Buff.affect(hero, RabbitRingTracker.class);
```

这样新 buff 的 `time = now`，随后每次 `act()` 里 `spend(TICK)` 自行续期，
形成「常驻 + 每回合 `act()` 一次」的计数器 —— 与原版 `Regeneration` 那类 buff 的写法一致。

**为什么不会变成「一回合无限免费」**：
SPD 调度在 `time` 相同时按 `actPriority` 排序，英雄是 `HERO_PRIO = 0`，
buff 是 `BUFF_PRIO = -30`，**英雄优先**。所以「免费的那一击 → 再动一次」之间英雄始终先行动；
只有英雄真正花掉时间（回合结束、`time` 前进）之后，tracker 才会 `act()` 把计数清掉。

| 验证项 | 结果 |
|---|---|
| 探针：`Buff.affect(hero, RabbitRingTracker.class)` 的 cooldown | `0.0` —— 下一 tick 即 `act()` |
| 探针：`act()` 是否清掉 `usedThisTurn` | `false` —— 计数被正确重置 |
| 探针：`act()` 之后是否按回合续期 | `cooldown = 1.0` —— 每回合一次 |
| 探针：修复前的 `Buff.affect(..., 9999f)` | `cooldown = 9999.0` —— 正常游玩内不会 `act()` |
| 全量编译（`javac @sources.txt`，1678 个源文件） | exit 0（仅 deprecation / unchecked 提示） |

探针脚本：`_tmp/RingScheduleCheck.java`（一次性脚本，`_tmp/` 由清理器定期回收）。

重新构建后，控制台应当在**每一回合**的第一次命中都出现 `【127 黑兔戒指】标记免费出手`，
而不是只有开局那一次。

### 1.6 遗留事项（待定 / 供决策）

**只在「命中」时给免费出手，Miss 不给。**
当前调用点在 `Char.attackOnce()` 的命中分支里（`hit == true` 才调 `shouldRefundTurn`）。
原表文字「**攻击时**回合数加一」更像「挥出去就还」。
若希望 Miss 也算，把该调用挪出命中分支即可（改动很小）。
