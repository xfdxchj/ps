## 🔴 致命坑（会崩溃）

### 坑 1：`frame is null` 崩溃

**现象**
```
NullPointerException: Cannot invoke "RectF.width()" because "frame" is null
    at Image.frame(Image.java:77)
```

**原因**：代码引用的帧号**超出了图片范围**。

**例**：图片只有 64 帧，代码用 `frames(frames, 80, 81, 82)`。

**自查**：图片总帧数 = `(宽 ÷ 格子) × (高 ÷ 格子)`

**修复**：
- 换更大的图片，或
- 把帧号改到范围内

> 真实案例：`mimic.png` 只有 64 帧，但 `MimicSprite.HollowWall` 用了帧 80-92 → 一进空洞就崩。

---

### 坑 2：图集尺寸必须是 **2 的幂**

**现象**：**所有物品/地形图案全部错乱**

**原因**：把 `items.png` 从 `256×512` 扩到 `256×640`
- 512 = 2⁹ ✅
- **640 = 512+128，不是 2 的幂** ❌

**修复**：扩到 `1024`（2¹⁰）

**教训**：**任何图集的高度都必须是 2 的幂**。

---

### 坑 3：`ItemSpriteSheet` 新常量必须 `assignItemRect`

**现象**：**打开背包崩溃**

```
NullPointerException: frame is null
    at ItemSlot / ItemSprite.view
```

**原因**：新增图标常量但没有登记尺寸。

**修复**：
```java
public static final int MY_ICON = AK_ICONS+5;
static { assignItemRect(MY_ICON, 16, 16); }   // ← 必须
```

---

### 坑 4：图标指向**空白格** → 物品"看不见"

**现象**：物品在背包里、有名字、能点击，但**图标是全透明的**

**原因**：图标常量指向了图集的空白区域。

**自查**（Python/PIL）：
```python
from PIL import Image
im = Image.open("items.png").convert("RGBA")
# 检查你的图标位置有没有像素
n = sum(1 for y in range(y0, y0+16) for x in range(x0, x0+16)
        if im.getpixel((x, y))[3] > 0)
print("非透明像素:", n)   # 必须 > 0
```

## 🟠 逻辑坑（不崩溃但玩不了）

### 坑 5：文案键用**完整包路径**

**现象**：显示 `!!!NO TEXT FOUND!!!`

**原因**：键名写成了"类名小写"，但引擎用的是**完整包路径**。

```
❌ items.endfloorskip.name
✅ items.endcontent.items.endfloorskip.name
```

**规则**：
```
键 = 类的完整包路径（去掉 com.shatteredpixel.shatteredpixeldungeon.）+ "." + 键名
```

**注意**：如果类在**顶层包**下（如 `endcontent`），键**不带** `items.` 前缀。

**自查**：
```powershell
python E:\破碎的地牢\_tools\find_nofound.py
```

### 坑 6：挑战区过渡**必须用 `REGULAR_ENTRANCE`**

**现象**：**踩楼梯完全没反应**（人站在原地）

**原因**：`Hero.java` 里有这条规则：
```java
&& (Dungeon.depth < 26 || transition.type == LevelTransition.Type.REGULAR_ENTRANCE)
```
**26F 之后，只有 `REGULAR_ENTRANCE` 类型的过渡能被点击触发。**

**修复**：
```java
transitions.add(new LevelTransition(this, cell,
        LevelTransition.Type.REGULAR_ENTRANCE));   // ← 挑战区一律用这个
```

---

### 坑 7：入口格和出口格**必须不同**

**现象**：**进入关卡立刻被弹到下一层**

**原因**：入口和出口绑到同一个格子，或 `activateTransition` 不区分格子。

**修复**：
- 入口格和出口格**用不同的 cell**
- `activateTransition` 里加 `transition.centerCell == EXIT_CELL` 判断

> 真实案例：冥犬层 31F，入口 1434 和出口 46 都登记为 `REGULAR_ENTRANCE`，导致从 30F 下来立刻弹到 32F。

---

### 坑 8：`level.locked` 会**禁止踩楼梯**

**现象**：打完 Boss 后**门还锁着**，走不了

**原因**：
```java
// Hero.actTransition
} else if (!Dungeon.level.locked && ...) {
            ↑ 关卡被锁 → 踩楼梯无效
```

**Boss 层进关会 `seal()` 锁门**，如果 Boss 死亡时没有 `unseal()`，就永远锁着。

**修复**：
- 在 `Boss.die()` 里调 `Dungeon.level.unseal()`（本 fork 的 `Boss` 基类**已统一处理**）
- 或在关卡 `build()` 里防御性 `unseal()`

---

### 坑 9：`attack(Char)` 是 **final**，不能覆写

**现象**：编译错误
```
cannot override attack(Char) in Char
```

**修复**：改用 `attackHook()`：
```java
// ❌ public boolean attack(Char enemy)
// ✅
public boolean attackHook(Char enemy) {
    // 你的附加逻辑
    return false;
}
```

---

### 坑 10：Boss 死了**不要重复 `unseal()`**

**原因**：本 fork 的 `actors.Boss` 基类**已经统一处理**了 `die() → unseal()`。

**修复**：`die()` 里只调 `super.die(cause)` + 你自己的逻辑。

## 🟡 工具坑（自己踩自己）

### 坑 11：不要用 PowerShell 的 `Set-Content` 改 `.java`

**现象**：编译报
```
非法字符: '\ufeff'
```

**原因**：`Set-Content` 会写入 **UTF-8 BOM**。

**修复**：用编辑器的 `write`/`edit` 工具，或：
```powershell
$utf8 = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $content, $utf8)
```

---

### 坑 12：注释和代码**粘在一行** → 代码被注释掉

**现象**：编译报奇怪的错，或某行代码"消失"

**原因**：`// 注释` 后没有换行，直接跟了代码：
```java
// 这是注释	public static final int X = 1;    ← X 被注释掉了！
```

**修复**：注释后**必须换行**。
